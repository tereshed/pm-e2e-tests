# Contributing

Правила для контрибьюторов репозитория `pm-e2e-tests` (e2e).

## Ветки

- Работа по задаче ведётся в отдельной ветке, созданной от актуального `main`.
- Для прогонов e2e используйте ветку вида `e2e/run-<run_id>`, где `<run_id>` — идентификатор прогона.
- Для остальных задач используйте ветку вида `task/<task_id>-<краткое-описание>`.
- Не пушьте напрямую в `main` — все изменения проходят через merge request.

## Коммиты

- Коммит должен быть сфокусирован на одной задаче или одном прогоне, без посторонних изменений.
- Сообщение коммита — короткое и по делу, в повелительном наклонении, например:
  - `add CONTRIBUTING.md`
  - `merge e2e report: e2e/run-<run_id>`
- Если коммит фиксирует отчёт прогона, укажите в сообщении run_id и/или revision.

## Отчёты прогонов

- Каждый прогон оформляется отдельным файлом в каталоге `runs/`:
  `runs/<дата>-<run_id>.md`, где `<дата>` — дата в формате `YYYY-MM-DD`.
- Отчёт готовится в ветке `e2e/run-<run_id>`, коммитится и мержится в `main` через merge request.
- После добавления отчёта обновите `runs/INDEX.md`, добавив ссылку на новый файл.

## Merge request

- Открывайте merge request из своей ветки в `main`.
- В описании MR укажите: что сделано, ссылку на задачу (если есть) и, для прогонов, run_id/revision.
- MR должен пройти проверку перед мержем; конфликты в `runs/INDEX.md` разрешаются объединением (union) записей.
